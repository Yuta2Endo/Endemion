## P0 — неделя, дешёвые и заметные победы

### 1. Сжать базу после удаления энциклопедии (VACUUM)
Файл базы 125 МБ, из них **124 МБ — свободные страницы** (`freelist_count` 31 773 из 31 879): таблицы удалены, место не отдано.
- Сделать бэкап, остановить запись (`docker compose stop app`), выполнить `VACUUM`, поднять контейнер.
- Ожидаемый результат: база порядка 1 МБ, бэкапы в S3 перестанут быть по 125 МБ.
- Критерий: `PRAGMA freelist_count` близок к нулю, `/` и `/community` отвечают 200, бэкап создаётся.
- Оценка: 30 минут.

### 2. CI на GitHub Actions
Сейчас нет `.github/workflows`: гейты (`lint`, `typecheck`, `test`, Playwright) запускаются только руками.
- Workflow на `push`/`pull_request`: Node 26, `npm ci`, `npm run check`, отдельная job с `npx playwright test --project=chromium` (поднять `wrangler dev`).
- Защита ветки `site-improve`: merge только с зелёным CI.
- Критерий: красный тест в PR блокирует merge.
- Оценка: 3–4 часа.

### 3. Смоук-тест и алерты после деплоя
Сейчас проверка после выкладки — вручную (`curl` по списку адресов). Про сбой узнаём от посетителей.
- `scripts/smoke.mjs`: `/`, `/games`, `/community`, `/account`, `/api/me`, `/sitemap.xml`, `auth/.well-known/openid-configuration` — коды и ключевые маркеры в HTML.
- Внешний uptime-монитор (Healthchecks.io / UptimeRobot) на `/` и `/healthz` auth, уведомление в Telegram-бот студии.
- Алерт на неудачный бэкап (сейчас ошибка видна только в логах Docker).
- Оценка: 2–3 часа.

### 4. Кеширование статики
`public/_headers` отдаёт `/assets/*.js` и `*.css` с `Cache-Control: no-cache` — каждый переход перепроверяет файлы. Причина в комментарии: импорты внутри модулей идут без `?v=`.
- Вариант А (простой): при сборке страниц подставлять `?v=ASSET_VERSION` во все `import` (сейчас только точки входа), затем `Cache-Control: public, max-age=31536000, immutable` для `/assets/*`.
- Вариант Б: хешировать имена файлов при выкладке.
- Критерий: повторный визит не скачивает CSS/JS заново, при обновлении версии кеш сбрасывается.
- Оценка: 4–6 часов.

### 5. Удалённые разделы — 410 вместо 301
`/manga`, `/encyclopedia`, `/anime` и другие отдают 301 на главную. Для поисковиков это «страница переехала», и они продолжают её держать.
- Заменить 301 на 410 Gone в `src/worker.js` (`RETIRED`) и в приложении; оставить 301 только там, где есть реальный новый адрес.
- Убрать эти адреса из sitemap (уже убраны, проверить).
- Оценка: 1 час.

## P1 — месяц, надёжность и скорость

### 6. Один прод, один рантайм
Сейчас один и тот же код живёт в двух местах: Cloudflare Worker (задеплоен, но прод обслуживает VPS) и VPS. Отсюда уже была ситуация «задеплоил воркер, а на сайте старый код».
- Решение: прод — только VPS. Воркер либо вывести из эксплуатации, либо оставить как preview на отдельной D1 с явной пометкой в документации.
- Обновить `docs/ENDEMION_DEPLOYMENT.md`: один путь выкладки, чек-лист, откат.
- Дополнительно: `npm run deploy:prod` — сборка + рестарт + смоук из пункта 3.
- Оценка: 1 день.

### 7. Бюджет производительности
- Цели: LCP < 2.5 с на мобильном, CLS < 0.1, вес первой загрузки < 300 КБ.
- `og-image.png` 121 КБ → WebP/AVIF (для соцсетей оставить PNG ≤ 300 КБ, но сжать).
- Проверить, что шрифты подключены с `font-display: swap` и preload только для используемых начертаний.
- Убрать неиспользуемые CSS-файлы со страниц (сейчас на `/` три файла стилей, ~62 КБ).
- Замер: Lighthouse mobile по 6 страницам до и после, цифры — в отчёт.
- Оценка: 1–2 дня.

### 8. Доступность до WCAG 2.1 AA
- Прогон axe-core по `/`, `/games`, `/games/:slug`, `/community`, `/account`, `/auth` в Playwright, ошибки — в тест.
- Проверить: контраст, фокус-рамки, порядок табуляции, `aria-selected` у вкладок панели аккаунта, подписи у иконочных кнопок, `alt` у обложек.
- Критерий: 0 critical/serious в axe, клавиатурой проходится весь основной сценарий.
- Оценка: 2 дня.

### 9. SEO: системность
- `lastmod` для всех адресов sitemap; генерировать карту из базы (игры, публикации, темы), а не из статического списка.
- JSON-LD: `Organization` на главной, `VideoGame` на страницах игр, `DiscussionForumPosting` для тем.
- Подключить Яндекс.Вебмастер и Google Search Console, следить за 404/5xx и исключёнными страницами.
- Оценка: 1 день.

### 10. PWA и офлайн
- В `public/sw.js` версия кеша задаётся руками (`VERSION = "v7"`), а в `PRECACHE` нет `studio.css` и `account-dashboard.css` — офлайн эти разделы останутся без стилей. Брать версию из `ASSET_VERSION` при выкладке и добавить недостающие файлы.
- Версию кеша брать из `ASSET_VERSION` при выкладке, а не менять руками.
- Офлайн-страница: ссылки на разделы, которые реально открываются без сети.
- Оценка: 4 часа.

## P2 — квартал, продукт и рост

### 11. Наполнение и пустые состояния
В базе: 1 пользователь, 1 игра, 8 тем, 0 комментариев. Пустой сайт не удерживает и не индексируется.
- Контент-план: 2 devlog в месяц, 1 новость в неделю, 1 тема форума в неделю (со ссылкой из Telegram-канала).
- Каждый пустой блок — с объяснением и действием («Пока нет тем — создайте первую», «Следите за devlog»).
- Оценка: постоянно, 2–3 часа в неделю.

### 12. Первый вход
- После регистрации: выбор username, аватара, подписка на уведомления (сейчас панель аккаунта открывается «пустой»).
- Подсказки в панели: что можно сделать (профиль, избранные игры, сессии).
- Оценка: 1–2 дня.

### 13. Достижения на виду
14 достижений уже есть в базе, но пользователь их не видит.
- Показать в публичном профиле и в панели, уведомление при получении, прогресс.
- Оценка: 1 день.

### 14. Продуктовая аналитика
Метрика и Cloudflare показывают визиты, но не путь пользователя.
- События: регистрация, первый комментарий, возврат на 7-й день, клик по игре.
- Свой лёгкий счётчик в D1 или Метрика-цели; отчёт раз в неделю.
- Оценка: 1 день.

### 15. Модерация без ручного обхода
- Порог автоскрытия жалоб, очередь в админке, уведомление модераторам в Telegram.
- Шаблоны ответов и журнал действий (журнал уже есть).
- Оценка: 2 дня.

## Как измеряем

- Доступность: внешний монитор, 99.9%+, простой фиксируется алертом.
- Скорость: Lighthouse mobile, LCP < 2.5 с, TTFB < 200 мс.
- Качество: CI зелёный на каждом PR, 0 critical в axe.
- Наполнение: ≥ 8 публикаций и ≥ 30 тем за квартал, ≥ 20 активных пользователей.
- Эксплуатация: бэкап < 5 МБ, восстановление проверено не реже раза в месяц.
