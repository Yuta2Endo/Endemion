# Безопасность Endemion ID

Что сделано, где это в коде и каким тестом проверено. Тесты: `auth/tests/*.test.mjs` (провайдер), `tests/endemion-id.test.mjs` (сайт), `apps/api/test/endemion-id.e2e-spec.ts` (Life).

## Протокол

| Мера | Где | Тест |
|---|---|---|
| Только Authorization Code, implicit и `id_token` в адресе запрещены | `responseTypes: ["code"]` в `auth/src/app.mjs` | «неверный redirect_uri и запрос без PKCE…» |
| PKCE обязателен для всех клиентов, только S256 | `pkce.required` | тот же, «подмена state и чужой code_verifier» |
| `redirect_uri` и `post_logout_redirect_uri` — точное совпадение, без `*`, в рабочей среде только `https` | `auth/src/config.mjs` | «неверный redirect_uri…» |
| ID token RS256, ключ из файла, в `/jwks` только открытая часть | `AUTH_JWKS_FILE` | проверка образа Docker |
| Сайты проверяют подпись, `iss`, `aud`, `exp`, `nonce`, `state`, PKCE | `openid-client` в `functions/_lib/endemionId.js` и `apps/api/src/auth/endemion-id.service.ts` | «подмена state…», «ответ провайдера нельзя использовать второй раз» |
| Код живёт 60 секунд и одноразовый, ответ провайдера с тем же `state` принимается один раз | `ttl.AuthorizationCode`, `takeLogin` | «ответ провайдера нельзя использовать второй раз и в другом браузере» |
| Секреты, verifier, токены не передаются в адресе и не попадают в браузер | обмен кода — с сервера сайта | — |
| Токен одного сайта не принимается другим | oidc-provider проверяет клиента | «токен одного сайта не принимается другим клиентом» |
| `next` и `returnTo` после входа — только свои пути | `safeNext`, `safeReturnTo` | «next на чужой сайт…», «returnTo на чужой сайт…» |

## Токены и сессии

| Что | Срок |
|---|---|
| Код авторизации | 60 секунд |
| Access token, ID token | 10 минут |
| Refresh token | одноразовый, не дольше центральной сессии |
| Центральная сессия Endemion ID | 30 дней |
| Сессия сайта / Life | 30 / 365 дней, но сверяется с Endemion ID раз в 5 минут |

- **Повтор refresh token** отзывает весь grant: и новый токен, и access token (код oidc-provider). Тест «refresh token одноразовый: повторное использование отзывает всё».
- **Гонка обновления.** Если два запроса одной сессии сайта пришли одновременно, обновляет токен только один (условный `UPDATE … WHERE refreshed_at IS ?`), иначе провайдер принял бы второй как повтор и отозвал вход.
- **Refresh token в базе сайтов** зашифрован AES-GCM ключом `ENDEMION_ID_TOKEN_KEY`. В базах сайтов и Endemion ID токены сессий хранятся только как SHA-256.
- **Cookie.** У сайтов — как раньше: `HttpOnly`, `SameSite=Lax`, `Secure`. Cookie начатого входа (`endemion_oidc`, `el_oidc`) — `HttpOnly`, путь только адрес ответа провайдера, 10 минут. Cookie Endemion ID — подписаны (`AUTH_COOKIE_KEYS`), `HttpOnly`, `SameSite=Lax`, `Secure` за Caddy.
- **Session fixation.** После входа сайт удаляет старую сессию браузера и выдаёт новый токен. Тест «гость входит…» проверяет, что cookie сменилась.
- **Отзыв.** Выход со всех сайтов, «завершить другие сессии», смена и восстановление пароля отзывают токены сайтов. Тесты «завершение другой сессии…», «выход…», «отзыв сессий в Endemion ID выводит и с сайта», «блокировка в Endemion ID завершает сессию в Life».
- **Недоступность провайдера.** Сессия сайта работает до часа после последней удачной сверки, потом нужен новый вход.

## Пароли и перебор

- Новые пароли — scrypt N=2^15, r=8, p=1, NFKC. Перенесённые PBKDF2 сайта проверяются без NFKC (как их хешировал сайт) и сразу заменяются на scrypt. Параметры хеша из базы ограничены сверху, чтобы испорченная строка не заставила считать часами.
- Пароль от 8 до 128 символов (как на сайте).
- Вход с несуществующей почтой и с неверным паролем отвечают одним текстом и считают хеш одинаково долго. Регистрация проверяет занятость почты после хеширования.
- Лимиты за 15 минут: 30 входов с IP, 10 неудач на почту или username, 10 регистраций с IP, 3 письма на адрес, 20 писем с IP. После 5 неверных паролей подряд вход в аккаунт закрыт на 15 минут. Тест «неверный пароль, блокировка после 5 ошибок…».
- Восстановление отвечает одинаково для любой почты. Ссылка одноразовая, 1 час, после смены пароля завершаются все сессии и токены сайтов. Тест «восстановление пароля…».

## CSRF и XSS

- Формы Endemion ID принимаются только с `Origin` (или `Referer`) самого Endemion ID. Формы аккаунта и загрузка аватара дополнительно требуют токен CSRF, привязанный к сессии (HMAC). Выход защищён токеном `xsrf` провайдера. Тесты «CSRF: форма аккаунта без токена или с чужого сайта отклоняется», «выход: подтверждение с защитой xsrf».
- На сайтах защита та же, что была: `Origin` для `/api/*` на сайте, `RequestGuard` в Life. Вход и ответ провайдера — переходы `GET`, защищены `state`.
- CSP Endemion ID: `script-src 'self'`, `style-src 'self'`, `frame-ancestors 'none'`, `form-action` — только свой адрес и адреса сайтов. Встроенных скриптов и стилей нет, данные пользователя экранируются. Тест «заголовки безопасности и cookie сессии».
- Аватар: до 2 МБ, тип по первым байтам (PNG, JPEG, WebP), SVG и HTML отклоняются. Тест «изменение username и аватара…». Сайт отдаёт аватар Endemion ID со своего адреса и берёт его только с адреса провайдера.

## Связь аккаунтов

- По username ничего не связывается. Тест «по username ничего не связывается».
- По почте — только если Endemion ID подтвердил её. Тесты «старый аккаунт сайта связывается только после подтверждения почты», «старый аккаунт Life связывается только по подтверждённой почте…».
- Номер старого пользователя сайта (`legacy_user_id`) Endemion ID выдаёт только для записей, созданных переносом.

## Известные ограничения

- Нет второго фактора (TOTP, ключи доступа).
- После выхода или блокировки в Endemion ID сессия второго сайта работает до 5 минут (до ближайшей сверки). Back-channel logout не включён.
- Блокировку входа после 5 неверных паролей можно вызвать для чужого аккаунта, зная почту или username. Лимит по IP это сдерживает, но не исключает.
- Нет капчи на страницах Endemion ID (на сайте Turnstile был необязательным).
- Смена почты требует пароль, но письмо на старый адрес не отправляется.
- Удаления аккаунта Endemion ID нет: удаление на сайте удаляет только данные сайта.
- Копии базы Endemion ID хранятся только на диске сервера.
- У сайта Life нет заголовка CSP (было до этих изменений).
