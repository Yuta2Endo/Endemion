# Endemion

Платформа для читателей манги, манхвы и маньхуа: каталог, полка и прогресс чтения, рекомендации, граф связей между тайтлами, сообщество и голосования.
Сайт: https://endemion.online (свой сервер, см. [DEPLOY.md](DEPLOY.md)). Старый адрес на `workers.dev` перенаправляет на него.

Код без сборки: ES-модули в браузере, обработчики в формате Pages Functions. Один и тот же код работает на Cloudflare Workers с D1 и на своём сервере (Node.js + SQLite, `server/`).

## Разделы сайта

| Адрес | Что там |
|---|---|
| `/` | Главная: подборки по настроению, популярное, новое, обновления, «Продолжить чтение», личные рекомендации |
| `/catalog` | Поиск по названию, автору и жанру, фильтры по типу, статусу, жанру и тегу, сортировка, страницы |
| `/title/:id` | Тайтл: главы, легальные источники, теги, персонажи, связанные тайтлы, рецензии и комментарии |
| `/nexus` | Nexus: граф связей вокруг выбранного тайтла, у каждой связи названы причины (жанры, теги, автор, общие читатели) |
| `/oracle` | Oracle: подбор по настроению и вкусу читателя, у каждого тайтла объяснение, почему он выбран |
| `/pulse` | Pulse: полка (Читаю, В планах, Прочитано, Отложено, Брошено, Избранное), история, календарь выхода глав, уведомления |
| `/profile`, `/u/:username` | ENDEMION ID: аватар, имя, о себе, любимые жанры и тайтлы, статистика, достижения, приватность |
| `/community` | Обсуждения, теории, подборки читателей, подписки, лента |
| `/arena` | Голосования, сравнение персонажей, турниры, рейтинги читателей и жанров |
| `/admin` | Админка (только для модераторов и администраторов, права проверяет сервер) |
| `/copyright` | Правообладателям: форма жалобы на материал |

Рекомендации и связи считаются по данным в базе: жанры, теги с весами, авторы, связи из админки и то, что читатели вместе держат на полках. Никакой внешней «нейросети» нет. Рейтинг читателей — среднее по настоящим оценкам из рецензий, до первых оценок его у тайтла нет. Сортировка «по рейтингу» использует байесовское среднее, чтобы одна оценка 10 не поднимала тайтл наверх. Результаты голосований — только настоящие голоса.

## Структура

```
src/worker.js           точка входа: маршруты API и страниц, остальное отдаётся из public/
functions/              обработчики в формате Pages Functions, их вызывает src/worker.js
  _lib/                 общий код: сессии, роли, проверки, поиск, Nexus, Oracle, модерация, уведомления, разметка страниц
  api/                  /api/* — вход, профиль, каталог, полка, Pulse, сообщество, Арена, модерация, админка
  site.js               страницы разделов (главная, каталог, Nexus, Oracle, Pulse, сообщество, Арена, профили)
  title/[id].js         страница тайтла, HTML собирается на сервере
public/                 статические страницы, стили, скрипты, шрифты (Manrope и Unbounded, лицензия OFL)
migrations/             схема базы (D1 и SQLite одинаковые), 0016_platform.sql — платформа ENDEMION
server/                 свой сервер: SQLite через адаптер D1, файлы на диске или в S3, миграции, seed
tests/                  юнит- и интеграционные тесты (node:test), проверки API и браузерные тесты (Playwright)
```

## Роли

- `user` — читатель.
- `moderator` — скрывает и восстанавливает контент, разбирает жалобы, временно запрещает публиковать, ведёт голосования. В админке видит только «Модерацию» и «Голосования».
- `admin` — всё, включая тайтлы, справочники, подборки, пользователей и роли.

Роль хранится в `users.role` и проверяется на сервере в каждом запросе. Выдать или снять роль модератора и администратора может только администратор, с подтверждением своим паролем. Свою роль изменить нельзя.

## Безопасность

- Пароли: PBKDF2-SHA256, 100 000 итераций, своя соль у каждого пароля. Сам пароль нигде не хранится.
- Сессия: случайный токен в cookie `HttpOnly; Secure; SameSite=Lax` на 30 дней. В базе хранится только SHA-256 токена.
- Перебор пароля: 5 неудачных входов в аккаунт или 30 попыток с одного IP за 15 минут, дальше ответ 429.
- CSRF: изменяющие запросы к `/api/*` принимаются только с заголовком `Origin` своего сайта.
- Антиспам: ограничение частоты публикаций, жалоб и голосов на пользователя; отклоняются сообщения больше чем с 3 ссылками, с 30 одинаковыми символами подряд и повтор того же комментария в течение 10 минут.
- Все запросы к базе с параметрами, без склейки строк с данными пользователя. Текст пользователей выводится через `textContent` или экранируется на сервере.
- CSP без `unsafe-inline`: в страницах нет встроенных скриптов и стилей.
- Turnstile (капча) включается, если задать ключи. Без ключей формы работают без капчи.
- После смены пароля завершаются все остальные сессии. Удаление аккаунта требует пароль; комментарии удалённого пользователя остаются без имени.

## Локальный запуск (свой сервер, рекомендуется)

Нужен Node.js 22.16 или новее.

```
npm install
cp .env.example .env             # для локального запуска хватает значений по умолчанию
npm run db:migrate               # создать или обновить базу (data/endemion.sqlite)
SEED_ADMIN_EMAIL=admin@example.com SEED_ADMIN_PASSWORD=придумайте-пароль npm run seed
PUBLIC_URL=http://127.0.0.1:8788 PORT=8788 MAIL_DEV_MODE=1 npm start
```

`npm run seed` добавляет 24 вымышленных демо-тайтла с жанрами, тегами, персонажами и связями и 3 голосования без голосов. Оценок, читателей и голосов seed не придумывает. Тестовый администратор создаётся, только если заданы `SEED_ADMIN_EMAIL` и `SEED_ADMIN_PASSWORD`. На рабочей базе (`NODE_ENV=production`) seed не запускается без `SEED_ALLOW_PRODUCTION=1`.

Администратором можно сделать и уже зарегистрированного пользователя: `npm run grant-admin -- почта@example.ru` (снять — с `--revoke`). В Docker: `docker compose exec app node server/grant-admin.mjs почта@example.ru`.

### Проверки

```
npm run lint                     # ESLint
npm run typecheck                # TypeScript (checkJs) для серверного кода
npm test                         # юнит- и интеграционные тесты на временной базе SQLite
npm run check                    # все три подряд
```

Интеграционные тесты (`tests/platform.test.mjs`, `tests/engines.test.mjs`) поднимают приложение на чистой базе с миграциями и проверяют регистрацию и вход, каталог, фильтры и поиск, полку и прогресс, избранное, рекомендации и Nexus, комментарии, голоса, роли и модерацию.

Проверки на запущенном сервере: `npm run test:api`, `npm run test:admin` и `npm run test:e2e` с `BASE_URL=http://127.0.0.1:8788 TEST_TARGET=node DATA_DIR=<папка данных сервера>`. Браузеры для `test:e2e` ставятся один раз: `npx playwright install chromium firefox webkit`.

Сборки нет: файлы из `public/` отдаются как есть. Проверка «как на рабочем сервере» — `npm start` с `NODE_ENV=production` и своими настройками в `.env`, либо `docker compose up --build`.

## Свой сервер (Docker + VPS)

Код сервера — в `server/`: SQLite вместо D1, диск или S3 вместо R2, раздача `public/` с заголовками из `_headers`. При запуске сервер сам делает резервную копию базы и применяет новые миграции. Пошаговая инструкция — [DEPLOY.md](DEPLOY.md).

## Cloudflare Workers

Тот же код работает как Worker с базой D1 `endemion` (id в `wrangler.toml`):

```
npm run db:migrate:local
npm run dev                      # http://localhost:8787
```

1. Войти в Cloudflare: `npx wrangler login`
2. Если в `migrations/` появились новые файлы: `npm run db:migrate:remote`. Перед миграцией скрипт сам выгружает рабочую базу в `backups/` (`npm run db:backup`); без резервной копии миграция не запускается. Папка `backups/` не попадает в git: в выгрузке почты и хеши паролей.
3. Деплой: `npm run deploy`. Сначала запускаются тесты (`predeploy`), при ошибке сайт не выкладывается.

Восстановление базы: `npx wrangler d1 execute endemion --remote --file backups/<файл>.sql` в пустую базу или откат на момент до миграции через `npx wrangler d1 time-travel restore endemion --timestamp=<время>`.

Сейчас Worker на Cloudflare только перенаправляет старый адрес `workers.dev` на `endemion.online` (`REDIRECT_TO` в `wrangler.toml`). Рабочий сайт — на своём сервере. Если удалить `REDIRECT_TO`, Worker снова станет полноценным сайтом со своей базой D1.

Не загружайте сайт через панель Cloudflare перетаскиванием папки: так заменится Worker, и API с базой перестанут работать.

## Админка

Страница `/admin`:

- **Сводка** — пользователи, контент, жалобы, хранилище, активность сообщества и самые читаемые тайтлы.
- **Тайтлы** — карточка, обложка, теги с весами (для Nexus и Oracle), легальные источники (только `https://`), главы и загрузка страниц, персонажи, связи с другими тайтлами.
- **Жанры и авторы** — справочники; переименование обновляет все карточки, удалить можно только неиспользуемое.
- **Модерация** — жалобы пользователей по группам, скрытие и восстановление, временный запрет публикаций, свежие комментарии, журнал решений.
- **Голосования** — создание голосований Арены из тайтлов, персонажей или жанров, закрытие и удаление.
- **Подборки** — вынести на главную или скрыть.
- **Жалобы** — жалобы правообладателей с `/copyright`.
- **Пользователи** — блокировка, завершение сеансов, роли модератора и администратора, удаление.
- **Журнал** — все действия администраторов.

Страницы главы сначала грузятся в черновик и видны читателям только после публикации, поэтому оборванная загрузка не ломает главу.

## Авторские права

Сайт не берёт главы с чужих ресурсов. Главы загружает администратор, и только те, на которые есть права. У тайтла можно указать ссылки на официальные и лицензионные площадки. Правообладатель отправляет жалобу через `/copyright`, она попадает в раздел «Жалобы» админки, решение записывается в журнал.

## Восстановление пароля

На своём сервере письма отправляет Unisender Go, настройка — в [DEPLOY.md](DEPLOY.md). Код умеет и Resend: если задан только `RESEND_API_KEY`, письма уходят через него. Пока ключ и отправитель не заданы, восстановление выключено и ссылка «Забыли пароль?» не показывается.

Resend для Worker на Cloudflare:

1. Зарегистрироваться в Resend, добавить домен (Domains → Add Domain) и внести показанные DNS-записи у регистратора. Дождаться статуса Verified.
2. Создать ключ API с правом Sending access и сохранить его секретом: `npx wrangler secret put RESEND_API_KEY`.
3. В `wrangler.toml` указать отправителя: `MAIL_FROM = "Endemion <noreply@ваш-домен>"`, затем `npm run deploy`.

Локально письма не отправляются: при `MAIL_DEV_MODE=1` ссылка из письма появится прямо на странице `/reset`. На сайте с настоящим адресом этот режим не работает, даже если переменная задана.

## Внешние сервисы

Все необязательны, ключи задаются в `.env` (свой сервер) или в `wrangler.toml` и секретах (Cloudflare), в коде их нет:

- Unisender Go или Resend — письма восстановления пароля.
- Cloudflare Turnstile — капча на входе и регистрации.
- S3-совместимое хранилище — страницы глав, обложки и копии базы.
- Яндекс Метрика — загружается только после согласия посетителя.
- Cloudflare Web Analytics — статистика без cookie.

## Статистика и ошибки

- Яндекс Метрика: номер счётчика в `YANDEX_METRIKA_ID`.
- Cloudflare Web Analytics: токен из JS-сниппета в `WEB_ANALYTICS_TOKEN`. Токен публичный, он виден в коде страницы.
- Логи своего сервера: `docker compose logs --tail 200 app`. Логи Worker: Workers & Pages → endemion → Observability или `npx wrangler tail`.

## Перед запуском для людей

- Заполнить данные оператора в `public/privacy.html` и проверить текст с юристом (152-ФЗ).
- Демо-тайтлы из `npm run seed` вымышленные. На рабочем сайте каталог наполняется через админку, публиковать можно только главы, на которые есть права.
