## 1. Причина появления `undefined`

Шапка и подвал отрисовываются на сервере через `functions/_lib/layout.js`:

- `siteHeader()` и `siteFooter()` перебирают статический массив `NAV` в формате `[адрес, метка, ключ]`.
- Для каждой ссылки используется локализованное название `s.nav[key]`, а не вторая строка из массива `NAV`.
- В `functions/_lib/i18n.js` в объектах `nav` для `ru` и `en` не было ключа `telegram`.

Поэтому для пункта `["https://t.me/EndemionOfficial", "Телеграм", "telegram"]` в шапке/подвале навигации вычислялось `s.nav["telegram"]`, то есть `undefined`. ВProduction HTML это видно как:

```html
<a href="https://t.me/EndemionOfficial">undefined</a>
```

Футерная отдельная соцссылка использовала `s.telegramCTA`, поэтому там было "Наш Телеграм" / "Our Telegram" — не было `undefined`, но навигационная ссылка в шапке и подвале была сломана.

## 3. Что именно исправлено

**i18n.js** — в оба языковых словаря добавлено:

```js
nav: { ..., telegram: "Телеграм" }   // ru
nav: { ..., telegram: "Telegram" }   // en
```

**layout.js** — навигационные ссылки теперь выводят локализованное название:

```js
export function navLabel(s, key) {
  return s.nav[key] ?? key;
}
```

Используется в шапке:

```js
const item = ([href, , key]) => `<a href="${href}"...>${e(navLabel(s, key))}</a>`;
```

и в подвале навигации. Если ключ вдруг отсутствует в конфигурации, выводится имя ключа (`telegram`), а не `undefined`, `null` или пустая строка.

---

## 4. Fallback

Реализован в `navLabel(s, key)`:

- если `s.nav[key]` существует — используется локализованное название;
- если отсутствует — используется `key`, который всегда является непустой строкой;
- `undefined`/`null`/пустая строка в интерфейсе не выводятся.
