# Запуск на своём сервере (Docker + VPS)

Сайт запускается тем же кодом, что и на Cloudflare. Вместо сервисов Cloudflare: база SQLite (файл `data/endemion.sqlite`), картинки на диске (`data/files`) или в S3-хранилище, HTTPS через Caddy с сертификатом Let's Encrypt.

## Что нужно

- VPS с Ubuntu 24.04 или Debian 12: 1 ядро, 1–2 ГБ памяти, диск под картинки глав (100 глав по 20 страниц — примерно 0,6–2 ГБ).
- Домен. У регистратора две A-записи на IP сервера: `example.ru` и `www.example.ru`. Без них Caddy не получит сертификат.
- Порты 80 и 443 открыты (в панели хостинга и в firewall сервера).

## 1. Подготовить сервер

```
sudo apt update && sudo apt upgrade -y
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker $USER        # затем выйти и зайти по SSH заново
sudo ufw allow OpenSSH && sudo ufw allow 80 && sudo ufw allow 443/tcp && sudo ufw allow 443/udp && sudo ufw enable
```

## 2. Скачать код

Репозиторий приватный. Проще всего — ключ только для чтения (deploy key):

```
ssh-keygen -t ed25519 -f ~/.ssh/endemion -N ""
cat ~/.ssh/endemion.pub
```

Показанный ключ добавить в GitHub: репозиторий → Settings → Deploy keys → Add deploy key (без права записи). Затем:

```
GIT_SSH_COMMAND="ssh -i ~/.ssh/endemion" git clone git@github.com:Yuta2Endo/Endemion.git endemion
cd endemion
git config core.sshCommand "ssh -i ~/.ssh/endemion"
```

## 3. Настройки

```
cp .env.example .env
nano .env
```

Обязательно: `SITE_DOMAIN` (домен без `https://`) и `PUBLIC_URL` (`https://` и домен). Остальное по комментариям в файле. Файл `.env` не попадает в git и в образ.

Папка данных должна принадлежать пользователю, от которого работает приложение в контейнере (uid 1000):

```
mkdir -p data && sudo chown 1000:1000 data
```

## 4. Перенести базу с Cloudflare

Делать прямо перед переключением: всё, что пользователи изменят на старом сайте после выгрузки, не перенесётся.

На своём компьютере, в папке проекта:

```
npm run db:backup
scp backups/endemion-<дата>.sql пользователь@сервер:~/endemion/data/
```

На сервере:

```
docker compose run --rm app node server/import-d1.mjs /app/data/endemion-<дата>.sql
rm data/endemion-<дата>.sql
```

В выгрузке почты и хеши паролей: после переноса файл удалить. Права администратора переносятся вместе с базой. Загруженных страниц и обложек в R2 сейчас нет, переносить файлы не нужно.

## 5. Запустить

```
docker compose up -d --build
docker compose logs -f app       # Ctrl+C — выйти из логов, сайт продолжит работать
```

При запуске сервер сам применяет новые миграции (перед этим делает резервную копию базы). Проверка: `https://example.ru/healthz` отвечает `ok`, сайт открывается, вход работает.

## Обслуживание

- **Обновить сайт:** `git pull && docker compose up -d --build`.
- **Логи:** `docker compose logs --tail 200 app`.
- **Права администратора:** `docker compose exec app node server/grant-admin.mjs почта@example.ru` (снять — добавить `--revoke`). Модераторов назначает администратор в админке: «Пользователи» → «Сделать модератором».
- **Обновление до платформы ENDEMION:** миграция `0016_platform.sql` применяется сама при запуске, после резервной копии. Существующие пользователи, тайтлы, главы и полки сохраняются; жанры и авторы из карточек переносятся в справочники. Seed на рабочем сервере не нужен: без `SEED_ALLOW_PRODUCTION=1` он там и не запустится.
- **Портал студии (2026-11-04):** миграция `0020_studio.sql` только добавляет таблицы и столбцы. Энциклопедия и платформа чтения удалены из кода, их адреса отвечают 301 на главную, таблицы и данные остались в базе.
- **Резервные копии:** сервер раз в сутки кладёт копию базы в `data/backups` и хранит последние 14 (`BACKUP_HOURS`, `BACKUP_KEEP` в `.env`). Срок считается от последней копии, поэтому обновления сайта расписание не сбивают. Вручную: `docker compose exec app node server/backup.mjs`.
- **Копии вне сервера:** копии на том же диске не спасут при поломке сервера. Создайте приватный бакет в S3-хранилище (Selectel, Yandex Object Storage, VK Cloud) и ключ с доступом только к нему, заполните строки `BACKUP_S3_*` в `.env` и выполните `docker compose up -d app`. После этого каждая копия уходит в бакет в папку `backups/`, там хранятся последние `BACKUP_S3_KEEP` (по умолчанию 30). Если отправка не удалась, копия остаётся на диске, а ошибка видна в логах.
- **Восстановить базу:** `docker compose stop app`, заменить `data/endemion.sqlite` копией из `data/backups` (файлы `endemion.sqlite-wal` и `endemion.sqlite-shm` удалить), `docker compose start app`.
- **Картинки в S3:** заполнить строки `S3_*` в `.env` и перезапустить. Файлы из `data/files` при этом нужно скопировать в хранилище отдельно.

## Письма для восстановления пароля (Unisender Go)

1. В Unisender Go добавить домен отправителя и внести у регистратора DNS-записи, которые покажет сервис (обычно TXT для SPF и DKIM). Дождаться подтверждения домена.
2. В настройках аккаунта взять ключ API.
3. В `.env` на сервере: `MAIL_FROM=Endemion <noreply@домен>` и `UNISENDER_API_KEY=ключ`. Если аккаунт в своём дата-центре, ещё `UNISENDER_API_URL` (адрес указан в личном кабинете). Затем `docker compose up -d app`.
4. Unisender Go добавляет в письма ссылку «Отписаться». Отписавшийся перестанет получать и письма для нового пароля. Чтобы убрать ссылку, попросите поддержку разрешить отправку без неё и задайте `MAIL_SKIP_UNSUBSCRIBE=1`.

Пока ключ или отправитель не заданы, восстановление пароля выключено и ссылка «Забыли пароль?» не показывается.

## Статистика (Яндекс Метрика)

Создать счётчик на metrika.yandex.ru (Вебвизор можно не включать: сайт его всё равно не запускает), вписать его номер в `YANDEX_METRIKA_ID` в `.env` и выполнить `docker compose up -d app`. Метрика загружается только после согласия посетителя: сайт сам показывает вопрос про cookie, а в подвале появляется ссылка «Настройки cookie». В админке и на странице нового пароля Метрика не работает.

## Что зависит от Cloudflare

Капча Turnstile и Web Analytics — сервисы Cloudflare: если Cloudflare плохо доступен из России, они тоже будут работать плохо. На своём сервере их можно оставить пустыми в `.env`.
