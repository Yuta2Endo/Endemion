## 3. How Favicons Are Connected

Every page `<head>` now contains:

```html
<link rel="icon" href="/favicon.ico?v=2" sizes="32x32">
<link rel="icon" href="/icons/favicon-32x32.png?v=2" type="image/png" sizes="32x32">
<link rel="icon" href="/icons/favicon-16x16.png?v=2" type="image/png" sizes="16x16">
<link rel="manifest" href="/manifest.webmanifest">
<link rel="apple-touch-icon" href="/icons/apple-touch-icon.png?v=2" sizes="180x180">
```

The SVG favicon link has been removed from all pages. Browsers will now use:
- **Desktop Chrome/Firefox/Edge:** PNG 32×32 (preferred over ICO when type is specified)
- **Safari:** ICO fallback, or apple-touch-icon for bookmarks
- **iOS home screen:** apple-touch-icon 180×180
- **Android PWA:** icon-192.png and icon-512.png from manifest
- **Legacy browsers:** favicon.ico (multi-resolution: 16, 32, 48)

## 5. Issues Fixed

- **SVG override:** The old setup linked `favicon.svg` in `<head>`, which modern browsers preferred over ICO/PNG. Removing the SVG link ensures the new branded ICO and PNG icons are actually displayed.
- **Missing sizes attribute:** apple-touch-icon now declares `sizes="180x180"` for correct iOS behavior.
- **Cache busting:** All icon hrefs include `?v=2` to force re-download after the update, without changing file paths.
- **Service worker:** Version bumped from v5 to v6 so the new SW installs on next visit and old caches are dropped. The precache list uses the same `?v=2` URLs the pages request (Cache Storage matches the query string, so an unversioned entry would never be hit), and `/favicon.ico` was added to the fetch handler — otherwise the offline page would show no icon. This was caught on review after the first commit and fixed in the follow-up commit.
